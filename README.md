# RAG評価
* 実際のユーザーの振る舞いに即した網羅的なテストデータの準備ができれば、精度改善に向けた準備は８０％完了したと思っていい。
* スコアリングの効率化手法の一例
  * LLM-as-a-judge
   * 理想的な回答必要があれば、LLMで採点
  * RAGAS
   * RAGの精度評価を自動採点する仕組み
   * 検索が悪いのか、生成が悪いかを切り分けくれるらしい

# RAG定着化
* 数名のメンバでクローズドデータでテスト
* スイッチングコスト最小化
* Teamsなどの既存ツールから直接機能呼び出し

# RAG以外の外部文章参照する仕組み
  * Agentic Search
   * Claude Codeに使用される手法。Grepを自律的に呼び出す反復プロセス
   * Pros）ベクトルDB不要
   * Cons）推論を繰り返すためトークン消費がネック
  * PageIndex
   * 目次ツリーをLLMが探索
   * Pros) 文章が複雑、離れたページにある情報同士の関連性理解
